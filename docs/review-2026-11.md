# bi-scorer の点検（2026-11-02）

対象：`takahiro-movement-lab/bi-scorer`（公開リポジトリ・main・bb4bf23）。中身は `index.html` 1枚だけ。
直した物は `review-2026-11` ブランチに入れた。main には入れていない。

## 1. 何をする道具か

- **Barthel Index（BI・日常生活動作の10項目・100点満点）を AI に採点させる、ブラウザで動く1枚のページ。**
- 使う人が自分の Anthropic API キーを入れ、患者情報を自由記載で貼り、「AI採点する」を押すと、ブラウザから直接 Anthropic の API（Claude Haiku）へ送り、10項目の点数・判定・根拠・「推定か記載ありか」を表にして出す。合計点と重症度（完全自立〜全介助）も出る。
- 「コピー」でカルテに貼れる文章にする。
- サーバーは無い。API キーは「保存する」にチェックすると、そのブラウザの localStorage に残る。

## 2. テストが通るか

- **元のリポジトリにテストは無かった。**
- 今回、画面だけで確かめられる最小のテスト（Playwright・4本）を `tests/smoke.test.mjs` に足した。API には実際に通信しない（偽の返答を差し込む）。
  1. 画面が開き、主要な部品がある
  2. API キーが空なら通信せずにエラー表示
  3. AI の返答に HTML が混ざっても文字として表示される（XSS 対策）
  4. 「保存する」を外すとキーは localStorage に残らない
- 結果：**4本とも通る**（この作業場所の Chromium で確認）。
- 動かし方：`npm install` → `npm test`。手元に別の Chromium を使いたい時は `PW_CHROMIUM=（実行ファイル）npm test`。

## 3. 壊れていた所・危なかった所（直した）

| # | 何が | どう直したか |
| --- | --- | --- |
| 1 | **AI の返答をそのまま HTML として画面に入れていた**（`innerHTML`）。返答に `<img onerror=…>` のような文字が混ざると、ブラウザで勝手に動く（XSS）。API キーが同じページにあるので、盗まれる経路になりうる | 項目名・判定・根拠を `textContent` で入れる形に書き直した。テスト3で確認 |
| 2 | **古いモデル名** `claude-haiku-4-5-20251001`（日付付きの旧 ID）。いずれ使えなくなる | 現行の `claude-haiku-5-5` に。費用は旧 Haiku より安い（$0.10 / $0.50 per 1M tokens・100K まで） |
| 3 | 「コピー」で、判定（judgment）や項目名が返ってこない行があると **エラーで止まる**（`undefined.padEnd`） | 無い時は空文字で埋める |
| 4 | 合計点に数値でない物が混ざると NaN になりうる | 数値だけ足す |
| 5 | **患者情報を外部の API に送ることが画面に書かれていない** | 入力欄の下に「氏名・ID・生年月日は入れない」「文章は Anthropic の API に送られる」の一行を足した |

## 4. 直していないが、知っておくべき所

1. **API キーをブラウザに保存する作り。** 共用 PC で「保存する」を押すと、次に使う人がキーを使える。業務で使うなら、保存のチェックを外す運用か、小さなサーバー（Cloudflare Workers など）を間に置いてキーをブラウザに置かない作りが筋。
2. **個人情報の扱い。** 送るのは自由記載なので、書いた人次第で個人が分かる情報が混ざる。病院の規程（外部サービスへの送信）に照らしてから使う。Anthropic の API は既定で学習に使われないが、保持期間などは契約による（未確認）。
3. **`anthropic-dangerous-direct-browser-access` ヘッダー。** ブラウザから直接 API を叩くための印で、名前のとおり「キーが見える前提」の使い方。1 と同じ理由で、本番運用なら中継サーバー。
4. **返答の JSON を正規表現で切り出している。** たまに失敗する余地がある。API の構造化出力（`output_config.format`）を使えば確実だが、ブラウザ直叩きのままでは変更点が増えるので今回は見送り。
5. **公開リポジトリ。** 鍵は入っていない（確認済み）。患者情報も入っていない。プレースホルダーの例文は架空。

## 5. 次に直すべき物（順に）

1. 中継サーバー（Cloudflare Workers・無料枠）を1つ置き、キーをサーバー側に移す。ブラウザにはキーを入れさせない。合わせて、送る前に氏名らしき文字列を警告する簡単なチェック
2. 構造化出力で JSON を確実に受け取る（中継サーバーを置けば SDK が使えるので簡単になる）
3. 採点基準を画面にも出す（今はプロンプトの中だけ）。使う人が AI の判定を自分で確かめられる
4. 「推定」の項目は点数を薄く表示するなど、人が見直す前提の見た目に
